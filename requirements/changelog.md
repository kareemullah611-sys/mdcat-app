## 2026-10-03 — Frontend flow audit: repair pass

An audit of the student and admin journeys found two broken flows and a batch of
defects that misreported data to the student. All were reproduced against the
running app before fixing and re-verified after.

- **FIXED** — **Password reset was unusable.** Better Auth emails the token as a path segment (`/reset-password/<token>?callbackURL=…`) but the only page read `?token=`, so every reset link 404'd. Added `app/(auth)/reset-password/[token]/`. Verified end to end with a real token: request → link renders → reset succeeds → new password signs in, old is rejected (401), and the link is single-use (replay 400). `callbackURL` is untrusted input and is only followed when it is a same-origin path.
- **FIXED** — **Practice sessions could never be completed, and every one of them 404'd from the exam history.** The practice runner set a local "finished" flag and never called `/submit`; only the exam runner does, so practice tests stayed `IN_PROGRESS` forever. `/exams` linked all 20 recent tests to `/tests/{id}/result`, which `notFound()`s unless `COMPLETED` — a student's whole history was dead links, and nothing could be resumed. Added `finishPracticeSession` + `POST /api/tests/{id}/finish`, which aggregates the answers already stored on the snapshot and therefore does **not** log `AnswerHistory` a second time (routing practice through `submitExam` would have counted every question twice in lifetime accuracy). The runner now offers "Finish session" and links to the persisted review. In-progress rows now link to the runner ("Resume") instead of a result page that does not exist.
- **FIXED** — **The result page named the wrong option.** It resolved letters against the authoring order while the runner presents the snapshot's stored shuffle, so for nearly every test "Your answer: B" pointed at an option the student never chose; it also hardcoded `["A","B","C","D"]`, printing "—" for the E/F options the admin schema allows. Letters now resolve through `optionOrder` (with a fallback if an option was since removed), via the existing `letterFor` helper, and each option's text is listed with "your answer"/"correct answer" markers so the letter is never load-bearing. Proven on a live test: an option the student saw as **A** sits at authoring index 1, which the old code reported as **B**.
- **FIXED** — **"Weak areas" was dead for the whole authored bank and could list topics the student was 100% on.** `getStudentStats` skipped any question without a `topicId`, and all 3,000 bank questions have none (they are grounded in outcomes and chapters), so a student who answered five MDCAT questions was told "Nothing to report yet". Grouping now falls back to the chapter, which every bank question has. The filter also gained an accuracy ceiling: it previously required only `attempted >= 2`, so a chapter answered 100% correctly was listed as a weakness with a green badge. Same bug fixed on the result page's "Weak chapters".
- **FIXED** — **Three unguarded `fetch` calls could permanently wedge the UI.** `test-builder`, `onboarding-form` and `practice-runner` set a loading flag and then awaited a request with no `try/catch`; a dropped connection rejects the promise, so the flag never cleared and the submit button — or every answer option — stayed disabled with no message and no retry. Added `lib/client-fetch.ts` (`postJson`), mirroring the helper `account-security-form` already had, and routed all three through it.
- **FIXED** — **A regression from the MDCAT-scope work:** the thin-board-pool notice counted the *profile's* board while the builder prefilters from the URL, so a Punjab student following a chapter link into an FBISE chapter was told "Punjab Board textbooks have not been mapped" while looking at 2,900 FBISE questions. The notice now derives from the effective `?board=`/`?class=` and names that board.
- **FIXED** — **Chapter "N MCQs" could not be drawn.** The study pages counted on `chapterId` alone, but the practice link they generate also pins board and class, and `Question.boardId`/`classId` are nullable. Counts are now built from `buildTextbookScopeWhere`, the same predicate the engine selects with, so the badge and the pool cannot drift. (With today's data the two counts coincide; this removes the dependency on that coincidence.)
- **FIXED** — **`/profile` was unreachable on a phone.** The avatar was the only entry point and was hidden below the `sm` breakpoint, while the mobile nav carries none of the account routes — so Account Security could not be reached at all on mobile. The avatar is now visible at every width, with the header row set to shrink and the wordmark truncate.
- **FIXED** — **Re-answering a practice question appended a second `AnswerHistory` row,** inflating lifetime attempts and accuracy. `recordPracticeAnswer` now writes at most one history row per question per session and refuses a completed session. The runner also guards double clicks with a ref, since `setBusy` has not committed when a second click arrives.
- **FIXED** — **`historyFilter: "CORRECT"` had no branch** and silently behaved like `MIXED`, returning the whole pool. Verified live: a student with four correct answers now draws only those.
- **FIXED** — **"Edit settings" wiped your subjects.** `/onboarding` rendered a blank form and its API replaces the subject rows wholesale, so visiting it from `/profile` and saving silently reset class, board, goal and subjects. The page now loads the existing profile and prefills the form, with a "Save settings" label when editing.
- **FIXED** — Signup ignored the result of the automatic sign-in and passed the *untrimmed* address, so a failed auto sign-in pushed the user to `/onboarding`, which bounced them to `/login` with no explanation. It now uses the normalized address, reports the failure and sends them to sign in. Blurring the username field also no longer erases a server-side "already taken" verdict, which left the submit button disabled with nothing explaining why.
- **FIXED** — `/study` rendered a bare header when no board had a published book; it now offers the MDCAT and practice routes instead.
- **FIXED** — Chapters of unpublished books appeared in the builder's chapter picker while `/study` hid those books. Unpublished books and their chapters now `notFound()` on direct link.
- **MODIFIED** — Raw `PAST_PAPER`/`MOCK` mode strings could reach the exam history, and the same row was labelled "Exam" on one page and "Practice session" on another; a single `testModeLabel` helper is now used everywhere.
- **ADDED** — `app/not-found.tsx`, `app/error.tsx` and `app/(app)/loading.tsx`. Every page awaits Prisma directly, so a failed query produced Next.js's bare error shell and a cold navigation to `/progress` (five sequential queries) was a blank screen.
- **VERIFIED** — 230 tests (8 new covering the history filters, the textbook-scope predicate, `letterFor` past D, and the weak-area thresholds), `tsc`, lint and `next build` clean.

## 2026-10-03 — The bank loader brings the syllabus up to date itself

- **FIXED** — Loading the bank in production failed with "183 outcome reference(s) are unknown". The production database had been seeded from an **older, partial** curriculum snapshot (106 of 289 outcomes); the 300 pilot questions only ever cited the outcomes they used, so nothing had ever needed the rest. The bank importer correctly refused to write a batch whose outcomes it could not resolve, but the prerequisite could only be satisfied over SSH.
- **ADDED** — `seedMdcatSyllabus2025` in `lib/data/mdcat-syllabus-seed.ts`, extracted from the CLI script so the admin loader can guarantee the prerequisite. A real (non-dry) load now seeds the syllabus first and records what it did in the job status; a dry run still writes nothing and simply reports the gaps.
- **ADDED** — A "Seed MDCAT syllabus" button and `POST /api/admin/mcq-bank { action: "seedSyllabus" }`, so an operator whose dry run reports unknown outcomes can fix the prerequisite and retry without shell access.
- **ADDED** — `MDCAT_SYLLABUS_OFFICIAL_TOTAL = 289` and a subject-level `created` count, so a partly seeded database is detectable and reported ("289 outcomes ready, 183 newly added") instead of failing opaquely.
- **VERIFIED** — Reproduced the production failure on a throwaway database with no syllabus seeded: dry run refused with `SYLLABUS_MISSING`, seeding reported "289 newly added", the same dry run then passed, re-seeding reported "0 newly added" (idempotent), and a full 3,000-question load ran through the HTTP admin endpoint against a deliberately truncated syllabus — auto-seeding the missing outcomes, 30/30 batches, 3,000 questions `PUBLISHED`, all 3,000 reachable by MDCAT scope. 8 job tests and 4 seed tests, `tsc`, lint and `next build` clean.
- **NOTE** — `scripts/seed-mdcat-syllabus-2025.ts` is now a thin wrapper over the shared seed; its console output gained the newly-added count.

## 2026-10-03 — MDCAT papers are scoped to the syllabus, not the board

- **FIXED** — A student on a board with no mapped chapters (Punjab, Sindh, KPK) got an empty or four-question MDCAT paper. `buildTest` filtered **every** test by board, so `PUNJAB` matched nothing in the authored bank. Spec §3 MODE B scopes MDCAT preparation to the current syllabus and relevant learning outcomes, with board selection merely "remaining available" — it was gating the pool. A test now carries an explicit `scope`: `BOARD` filters by board as before, `MDCAT` filters by membership of a learning outcome in the `PMDC_MDCAT_2025_FINAL` syllabus via `QuestionMapping.syllabusOutcome` and ignores the board entirely.
- **FIXED** — The syllabus link was written at import time and never queried. `QuestionMapping.syllabusOutcomeId` had no `where` clause anywhere in the codebase, so §74 steps 2-3 ("resolve syllabus if MDCAT mode", "find eligible concepts") did not exist. That traversal is what MDCAT scope now selects on.
- **FIXED** — Chapter and topic filters were `push`ed into the same `where.OR` array as the board branches, so they **widened** the pool instead of narrowing it: picking one Balochistan chapter also admitted FBISE-primary questions, and picking a chapter did not exclude other chapters of the chosen board. They are now `AND`-ed.
- **FIXED** — The class filter read only the denormalised `Question.classId`, ignoring `QuestionMapping.schoolClassId`, so a question taught in the other year under cross-board mapping was invisible to the class filter. It now accepts either.
- **MODIFIED** — MDCAT scope covers **both years** by default ("Both years"), matching MDCAT's own reach and the §74 example. `classIds` and `boardIds` are optional outside board scope; board scope still requires both, enforced in the schema rather than only the UI.
- **ARCHITECTURAL** — `buildQuestionWhere` is extracted from `buildTest` as a pure function so the pool can be asserted without a database; `buildTest` now resolves the syllabus version and the history preference and delegates.
- **ADDED** — `Test.scope` (migration `add_test_scope`, one statement, defaulted to `BOARD`) so a snapshotted paper records which syllabus produced it.
- **ADDED** — `/practice` counts the board-scoped pool for the student's board and class and, below 50 questions, says so plainly and links to `/exams`, instead of letting a student discover a four-question paper by trial. `/exams` defaults to MDCAT scope.
- **FIXED** — `schema.prisma` never declared the `User.username` index that migration `add_username` created, so `prisma migrate dev` saw drift and tried to **drop** it. That index serves Better Auth's plain `WHERE username = ?` sign-in lookup, which the functional `LOWER(username)` unique index cannot answer. It is now declared with `map:` pinning the existing name, so the drift is closed instead of the index removed. The scope migration is a single `ADD COLUMN`.
- **VERIFIED** — With a real `PUNJAB` / grade 11 profile, through `POST /api/tests`: board scope draws the 4 questions that exist, MDCAT scope draws the full 100 requested — 58 grade 11, 39 grade 12 and 3 grade 12, from FBISE *and* Balochistan. The practice page renders the amber notice; `/exams` renders MDCAT scope selected with "Both years". 215 tests (18 new), `tsc`, lint and `next build` clean.
- **OPEN** — Mapping real Punjab (and Sindh, KPK) textbook chapters to outcomes is content work still to do. Until then those boards get a thin board-practice pool and a notice pointing at the MDCAT scope. Two related defects found while tracing this are left alone as out of scope: `historyFilter: CORRECT` has no branch in `buildTest` so it behaves as `MIXED`, and the bank never sets `Question.topicId`, so the §76 topic-balancing grouping in `balancedSample` degenerates to a per-subject shuffle.

## 2026-09-14 — Load the question bank from the admin UI

- **ADDED** — An admin-only loader, **Admin → Load bank** (`/admin/mcq-bank`), backed by `POST/GET /api/admin/mcq-bank`. An admin can filter by subject and class, run a dry run, then load and optionally publish; the page polls its own per-batch progress. This makes the 3,000-question bank loadable on a deployed instance with no shell access and no file transfer — the authored questions already ship inside the deploy image as TypeScript data, which is what the missing live bank actually was.
- **ARCHITECTURAL** — Importer logic moved out of the CLI into `lib/data/mcq-bank/import.ts` (`runBankImport`), so the script and the web loader share one validated code path rather than two copies that can drift. `scripts/import-mcq-bank.ts` is now a thin argument-parsing wrapper.
- **ARCHITECTURAL** — Long loads run as an in-process background job (`lib/mcq-bank-job.ts`), not inside the request: a full-bank load writes thousands of rows and would exceed a request timeout. State is a module variable, which suits the single long-running Node service on Railway but is lost on restart; the import is idempotent, so re-running is the recovery path. Noted in the README gotchas rather than persisted to a jobs table.
- **FIXED** — A late validation failure could leave a partly-loaded bank. Batches are written one transaction at a time and the outcome codes were only resolved inside that transaction, so a run whose *last* batch cited an unseeded outcome would commit roughly 2,900 rows and then abort. Every outcome cited by a **selected** batch is now resolved and checked before the first write. Verified against a throwaway database: deleting one outcome cited by `phy-xii-b5` makes a full-bank run write **0** rows instead of ~2,900.
- **VERIFIED** — End to end over HTTP as a signed-in admin: dry run of the full bank reports 30/30 batches and 3,000 questions with no writes; a batch deleted from the database is rewritten by the web path (100 rows, `PUBLISHED`); the same batch loaded without the publish flag lands as `VALIDATED`, so admin-only visibility holds. Guards: unknown subject/batch/grade rejected 400, a second concurrent load rejected 409, a signed-in **student** gets 403 on both methods and is redirected off the page, and an unauthenticated caller gets 403. 197 tests (5 new for the job runner), `tsc` and lint clean.
- **CORRECTED** — The CLI's per-batch log line printed `(dry run)` based on `result.grade === 12` rather than the actual dry-run flag, so Grade XII batches were mislabelled and Grade XI ones unlabelled. It now reports the grade explicitly and only the summary claims a dry run.
- **OPEN** — Still needs to run against production, which requires Railway CLI access. Also still open: profiles whose board has no mapped chapters (e.g. `PUNJAB`, which has only demo books) keep drawing from the thin sample pool even once the bank is loaded — the bank maps to FBISE and Balochistan. Flagged in the deploy checklist; needs a product decision on fallback or a profile migration rather than a silent remap of provenance.



- **ADDED** — `--metadata-only` for `scripts/import-fbise-books.ts` and `scripts/import-balochistan-books.ts`: registers books and chapters from their declarative lists without requiring the PDF files to exist. The question pipeline only needs the chapter rows; only the reader needs the files. Default (file-enforcing) behaviour is unchanged and still guards local use.
- **WHY** — The 12 textbook PDFs total 1.7 GB and are gitignored, so no deploy image contains them; production serves them from a Railway volume mounted at `/data/textbooks`. Both importers previously hard-failed on `access(filePath)`, which made a PDF-less database (fresh dev DB, CI) unable to register books and therefore unable to accept the question bank. This is a capability gap for PDF-less databases, **not** the reason the production bank was empty — production already has its books and a working reader, and was missing only the syllabus outcomes and the question rows.
- **VERIFIED** — `--metadata-only` succeeds with a PDF absent; default mode still fails with `ENOENT` when it is missing; the question bank still validates against the re-registered chapters; 192 tests, `tsc` and lint clean.
- **FIXED** — `lib/__tests__/mcq-bank.test.ts`: the grounding/duplicate specs are O(n²) over 500 questions per subject and class and were exceeding vitest's 5 s default under load. Given an explicit 60 s budget; the suite now passes repeatably.
- **OPEN** — Not yet run against production: this requires Railway CLI access. Once the 289 outcomes and the bank are loaded there, the live instance stops showing only the 17 sample questions. The admin UI loader added below is now the easier path.
